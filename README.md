# Pi Extensions

A collection of extensions for [Pi](https://pi.dev), the AI coding agent for the terminal.

## Installation

Install the entire collection:

```bash
pi install git:github.com/Nulluminati/pi-extensions
```

Install a single extension by pointing a package entry at its file in `~/.pi/agent/settings.json`:

```json
{
  "packages": [
    "~/Projects/pi-extensions/extensions/goal/goal.ts"
  ]
}
```

A file path loads that one extension. Its relative imports, such as shared `lib/` modules and per-extension `src/` files, resolve normally from the repo on disk. A directory path loads the whole package instead. To load the directory but narrow what runs, use the object form with glob filters:

```json
{
  "packages": [
    {
      "source": "~/Projects/pi-extensions",
      "extensions": ["+extensions/goal/goal.ts"]
    }
  ]
}
```

`+path` includes one exact file. `!pattern` excludes a match, and `[]` loads none of a resource type. Run `pi config` to toggle discovered extensions without editing JSON.

Try an extension for one session without changing settings:

```bash
pi -e extensions/goal/goal.ts
```

## Extensions

| Extension | Description |
|-----------|-------------|
| `todos/` | Persistent todo list the agent manages with the `todo` tool (add/check/uncheck/list/clear), rendered as a ☐/☑ widget above the editor. Shared state lives in `lib/todos.ts`. |
| [`jev/`](extensions/jev/README.md) | Ask Jev for batched choices, rubric scores, and yes/no probabilities about supplied evidence. Returns typed answers and reported usage through Pi's classifier registry. Judgments remain advisory; the tool never executes actions. |
| [`approval-mode/`](extensions/approval-mode/README.md) | Gates agent Bash, background, and monitor commands. Hard denies run first; a small reviewed command set runs without Jev. TypeSafe Jev checks the rest. Rejected or uncertain calls ask for one-time approval in the parent session; unavailable decisions block. `/approval-mode off` skips Jev for the parent and its workers, but keeps hard denies and sandbox limits. Workers cannot change the mode themselves. |
| `handoff/` | Summarize the current session with the global small model and start a new focused session. `/handoff [goal]` builds a compact continuation prompt, lets you review it, then opens a new session with the summary pre-filled. |
| `goal/` | Goal-oriented auto-continuation mode. `/goal` command with pause/resume/reset, a small-model evaluator that judges completion after every turn, and iteration/no-progress runaway guards. |
| `background-jobs/` | Long-running work without blocking the turn. The `background` tool runs a shell command detached in its own process group and wakes the agent when it exits (or the first time output matches a pattern); `monitor` polls a command until a condition holds (exit code, output match) and wakes the agent; `jobs` lists, tails, and cancels jobs. Wake messages carry only the job id and exit status — output is read on demand and spooled to `~/.pi/agent/background-jobs/`, pruned on session start past 7 days or 200 files. Active jobs render in a framed widget above the editor (todos-style); `/jobs` opens the interactive panel (user-only; the agent cannot open modals). |
| [`ask-user/`](extensions/ask-user/README.md) | Adds the `ask_user` tool for one to four related questions. Supports single-select, multi-select with supplemental custom text, freeform answers, tab navigation, and review before submission. |
| `btw/` | Side conversation channel. A parallel tool-using agent in a non-capturing overlay for mid-run questions (`/btw`), with contextual/tangent modes, hidden threading, a thinking override, and full or summarized handoff to the main agent. Uses the global small model. |
| `synthetic/` | Synthetic provider integration. Registers `synthetic` as a Pi provider with OpenAI-compatible API, a static model catalog with a startup staleness check, vision/reasoning support, and quota tracking via `/synthetic:models` and `/synthetic:quota`. |
| `neuralwatt/` | Neuralwatt provider integration. Registers `neuralwatt` as a Pi provider with an OpenAI-compatible API, a static model catalog (DeepSeek V4/V4.1 Flash, Gemma 4, GLM-5.2/5.3, Kimi K2.7/K3, Qwen3.6/3.8), a startup staleness check, and quota/energy display via `/neuralwatt:models` and `/neuralwatt:quota`. Flex pricing tier toggle (`/neuralwatt:flex`) sends `service_tier: "flex"` for flex-capable models, with an on/off badge next to the thinking level in the status bar. |
| [`session-name/`](extensions/session-name/README.md) | Give unnamed interactive Pi sessions a temporary project name. The global small model names the session after its first user message. Preserve manual names. The Herdr adapter mirrors Pi names onto panes without renaming tabs. |
| `session-recap/` | Claude-Code-style session recap generated by the global small model. Shows one line above the editor when you refocus a Pi session or after idle time. Includes configurable triggers and a `/recap` command. |
| `context/` | Claude Code-style `/context` for Pi: a framed modal showing what is consuming the context window — system prompt with per-file AGENTS.md/CLAUDE.md breakdown, skills, active tool definitions, messages (with the largest by estimated size), free space, and the compaction reserve — plus session token/cost totals. |
| `context7/` | Context7 documentation tools with persistent searchable cache. `context7_resolve_library_id` maps package names to Context7 IDs; `context7_get_library_docs` fetches curated docs by ID or name; `context7_get_cached_doc_raw` retrieves raw cached docs in bounded windows (2,000 lines / 40k chars per call, `offsetLine` paging) so huge docs can't blow up the context. Optional `$CONTEXT7_API_KEY` for higher rate limits. |
| [`codex-image/`](extensions/codex-image/README.md) | Generate and edit PNG images with Codex login through the `generate_image` tool. Files go in the project's `.pi/images/` directory. |
| `web-search/` | Web search and fetch with a selectable provider. `web_search` tool queries the active backend (Brave, Synthetic, or a self-hosted SearXNG instance) and returns titled snippets; `web_fetch` retrieves and extracts text from any HTTP/HTTPS URL. Switch providers mid-session with `/websearch:select`. Brave needs `$BRAVE_API_KEY` ([get one](https://brave.com/search/api/)); Synthetic reuses the synthetic provider's credentials or `$SYNTHETIC_API_KEY`; SearXNG needs `$SEARXNG_URL` pointed at your instance. |
| `code-search/` | Code search across public GitHub repositories via Sourcegraph's public API. `code_search` tool queries millions of repos with optional filters for language, repository (`owner/repo`), and path. No API key required. |
| `worker-sandbox/` | OS-level worker sandbox (`@anthropic-ai/sandbox-runtime`; bubblewrap on Linux, sandbox-exec on macOS). Loaded only in worker sessions (`PI_WORKER=1`), where it overrides the built-in tools (`read`, `write`, `edit`, `bash`, `grep`, `find`, `ls`) and `!` with fail-closed wrappers that execute inside the sandbox via a per-session broker. Policy comes from the project's `.pi/sandbox.json` (srt schema: read/write rules plus `network.allowedDomains`); Unix sockets and local binding are refused by design. A missing policy or failed initialization kills every tool call — never falls back to host execution. |
| `status-bar/` | Responsive Workspace, Context, and Session panels preserve Git state, token usage, costs, turns, and unread mail. Panels stack on narrow terminals. Model labels stay in the framed editor. Toggle with `/statusbar:toggle`. |
| [`tool-style/`](extensions/tool-style/README.md) | Gives agent tools, direct `!command` output, and extension messages a pywal-derived darker surface with state-colored rails. Toggle with `/toolstyle:toggle`. |
| `clear/` | Aliases `/clear` to `/new` for muscle memory from Claude Code and `clear`-keyed tools. Asks for confirmation first via a framed confirm modal, then the underlying `/new` behavior handles discard confirmation. |
| [`voice/`](extensions/voice/README.md) | Local dictation and speech playback with sherpa-onnx and ONNX Runtime. `/voice` opens the dictation overlay; `/voice:settings` opens one settings modal for dictation, speech, voice, and connection status. Hold Space to dictate; use `/voice:speak` to summarize and read the latest response aloud. |
| [`worker-model/`](extensions/worker-model/README.md) | One enforced global model for spawned worker sessions. `/worker-model` selects it; the current choice appears in the input bar. spawn_worker fails descriptively when unconfigured. |
| `worker-blocker/` | Shared worker blocker protocol: extensions inside a worker session report an environmental blocker through the `report_blocker` tool; the marker reaches the parent's `workers` tool and wake messages without injecting worker output into the parent conversation. Implementation lives in `lib/worker-blocker.ts`. |
| [`small-model/`](extensions/small-model/README.md) | One global model for handoff, BTW, session names, session recap, and voice summaries. Use `/smallmodel` to select it; the current choice appears in the input bar. |
| [`missions/`](extensions/missions/README.md) | Durable missions: long-lived objectives with a task graph, checkpoints, decisions, and budget, persisted in the project across restarts. `reconcile` re-runs done tasks' verification commands and flags regressions. |
| [`messenger/`](extensions/messenger/README.md) | File-based coordination between Pi sessions sharing a project: presence, mailboxes with automatic delivery into the conversation, and path reservations that block other sessions' edits. |
| [`herdr/`](extensions/herdr/README.md) | Mirror Pi session names onto owning panes. Display Pi state and combined session/worker cost as expiring Herdr pane tokens. Keeps the official Pi integration responsible for activity state and session restore. Ask User and Approval Mode report blocked dialogs through that integration. |
| [`workers/`](extensions/workers/README.md) | Multi-worker workflows: spawn bounded tasks as worker sessions whose tools run in the OS sandbox. Isolated workers are provisioned by the project-owned setup hook `.pi/provision-worktree` (bounded, sandboxed, log-pointer failure) after `.worktreeinclude` paths are carried; their `.pi/sandbox.json` governs read/write/network policy. Mutating workers use isolated git worktrees. `read_only: true` starts an investigation worker with research tools and a read-only workspace sandbox. Collect reports and patches through the durable worker registry. |
| [`autoresearch/`](extensions/autoresearch/README.md) | Autonomous experiment loop: measure a metric, keep improvements (commit), discard regressions (revert), repeat with correctness gates and descriptive spread scoring. |

Per-extension configuration (flags, env vars, config files) lives in each extension's own `README.md` under the **Configuration** section.

## Development

### Type declarations

Extensions import types from the Pi SDK packages, which are dev dependencies of this repository:

```typescript
import type { ExtensionAPI, ExtensionCommandContext } from "@earendil-works/pi-coding-agent";

export default async function (pi: ExtensionAPI) {
  pi.registerCommand("hello", {
    description: "Say hello",
    handler: async (_args, ctx: ExtensionCommandContext) => {
      ctx.ui.notify("Hello!", "info");
    },
  });
}
```

Pi loads these packages for extensions at runtime, so the imports need no build step. Types that no public package entry exports are derived in `lib/pi-types.ts`.

### Creating a new extension

Use the scaffolding script to generate boilerplate:

```bash
npm run create my-feature
```

This creates `extensions/my-feature/my-feature.ts` and `test/extensions/my-feature.test.ts`.

Or create manually:

1. Create `extensions/<descriptive-name>/` and add `<descriptive-name>.ts`
2. Implement your extension using `import type { ... } from "@earendil-works/pi-coding-agent"`
3. Validate: `npm run validate:one extensions/<name>/<name>.ts`
4. Test live: `pi -e extensions/<name>/<name>.ts`
5. Format and lint: `npm run format`
6. Run full check: `npm run check`

### Validation

Validation logic lives in `lib/validate-extension.ts`. CLI entry points are in `scripts/`:

```bash
npm run validate          # Validate all extensions (no subprocesses)
npm run validate:one <path>  # Validate a single extension
```

Checks run on every extension:
- Valid TypeScript syntax
- Required default export (async function)
- No undeclared npm imports
- At least one pi API call (`registerTool`, `registerCommand`, `on`, `appendEntry`, or `registerProvider`)

### Secret scanning

A [gitleaks](https://github.com/gitleaks/gitleaks) config lives at `.gitleaks.toml` and runs two ways:

- The husky pre-commit hook runs `gitleaks protect --staged` so secrets are caught before they leave the machine. The hook skips silently if gitleaks isn't installed locally; install it for early feedback:
  - Fedora: `sudo dnf install gitleaks`
  - macOS: `brew install gitleaks`
- The CI workflow runs gitleaks on every push and pull request as a required check, so commits without a local install still get blocked at the server.

The config extends gitleaks' default ruleset (~150 detectors for common token formats) and allowlists documentation placeholders like `syn_...` and `ctx7sk-...`.

### Testing

Shared mock factories live in `test/mocks/`:

- `createMockPi()` — returns a mock `ExtensionAPI`
- `createMockContext()` — returns a mock `ExtensionContext`
- `createMockCommandContext()` — returns a mock `ExtensionCommandContext`
- `createMockUI()` — returns a mock `ExtensionUIContext`

Per-extension tests go in `test/extensions/<name>.test.ts`.

```bash
npm run test       # Run all tests once
npm run test:watch # Run tests in watch mode
```

## Rules

- **No external npm dependencies** without explicit justification. Pi transpiles extensions directly.
- **One responsibility per file.** A focused extension is easier to test and maintain.
- **Test interactively** with `pi -e` before committing.
- **Extensions must export a default async function.**
