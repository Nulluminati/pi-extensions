# Pi Extensions

A collection of extensions for [Pi](https://pi.dev), the AI coding agent for the terminal.

## Installation

Install the entire collection:

```bash
pi install git:github.com/Nulluminati/pi-extensions
```

Or try a single extension without installing:

```bash
pi -e git:github.com/Nulluminati/pi-extensions/extensions/goal/goal.ts
```

## Extensions

| Extension | Description |
|-----------|-------------|
| `todos/` | Persistent todo list the agent manages with the `todo` tool (add/check/uncheck/list/clear), rendered as a ☐/☑ widget above the editor. Shared state via `lib/todos.ts`; the plan extension populates the list from an approved plan and completes when every item is checked. |
| `plan/` | Strict plan mode with an approval gate. `/plan` (or `Ctrl+Alt+P`, `--plan`) makes Pi read-only: `edit`/`write` are hard-blocked and bash is restricted to a read-only allowlist. The `plan_submit` tool proposes a structured plan in an overlay — approve to execute with `[DONE:n]` step tracking, edit to send it back, or keep planning. |
| `handoff/` | Summarize the current session with the global small model and start a new focused session. `/handoff [goal]` builds a compact continuation prompt, lets you review it, then opens a new session with the summary pre-filled. |
| `goal/` | Goal-oriented auto-continuation mode. `/goal` command with pause/resume/clear, a small-model evaluator that judges completion after every turn, and iteration/no-progress runaway guards. |
| `background-jobs/` | Long-running work without blocking the turn. The `background` tool runs a shell command detached in its own process group and wakes the agent when it exits (or the first time output matches a pattern); `monitor` polls a command until a condition holds (exit code, output match) and wakes the agent; `jobs` lists, tails, and cancels jobs. Wake messages carry only the job id and exit status — output is read on demand and spooled to `~/.pi/agent/background-jobs/`, pruned on session start past 7 days or 200 files. Active jobs render in a framed widget above the editor (todos-style); `/jobs` opens the interactive panel (user-only; the agent cannot open modals). |
| [`ask-user/`](extensions/ask-user/README.md) | Adds the `ask_user` tool for one to four related questions. Supports single-select, multi-select with supplemental custom text, freeform answers, tab navigation, and review before submission. |
| `btw/` | Side conversation channel. A parallel tool-using agent in a non-capturing overlay for mid-run questions (`/btw`), with contextual/tangent modes, hidden threading, a thinking override, and full or summarized handoff to the main agent. Uses the global small model. |
| `synthetic/` | Synthetic provider integration. Registers `synthetic` as a Pi provider with OpenAI-compatible API, dynamic model discovery, vision/reasoning support, and quota tracking via `/synthetic-models` and `/synthetic-quota`. |
| `neuralwatt/` | Neuralwatt provider integration. Registers `neuralwatt` as a Pi provider with an OpenAI-compatible API, a static model catalog (DeepSeek V4 Flash, Gemma 4, GLM-5.2, Kimi K2.5/K2.6/K2.7/K3, Qwen3.5/3.6), a startup staleness check, and quota/energy display via `/neuralwatt-models` and `/neuralwatt-quota`. Flex pricing tier toggle (`/neuralwatt-flex`) sends `service_tier: "flex"` for flex-capable models, with an on/off badge next to the thinking level in the status bar. |
| `session-recap/` | Claude-Code-style session recap generated by the global small model. Shows one line above the editor when you refocus a Pi session or after idle time. Includes configurable triggers and a `/recap` command. |
| `context/` | Claude Code-style `/context` for Pi: a framed modal showing what is consuming the context window — system prompt with per-file AGENTS.md/CLAUDE.md breakdown, skills, active tool definitions, messages (with the largest by estimated size), free space, and the compaction reserve — plus session token/cost totals. |
| `context7/` | Context7 documentation tools with persistent searchable cache. `context7_resolve_library_id` maps package names to Context7 IDs; `context7_get_library_docs` fetches curated docs by ID or name; `context7_get_cached_doc_raw` retrieves raw cached docs in bounded windows (2,000 lines / 40k chars per call, `offsetLine` paging) so huge docs can't blow up the context. Optional `$CONTEXT7_API_KEY` for higher rate limits. |
| `web-search/` | Web search and fetch with a selectable provider. `web_search` tool queries the active backend (Brave, Synthetic, or a self-hosted SearXNG instance) and returns titled snippets; `web_fetch` retrieves and extracts text from any HTTP/HTTPS URL. Switch providers mid-session with `/websearch`. Brave needs `$BRAVE_API_KEY` ([get one](https://brave.com/search/api/)); Synthetic reuses the synthetic provider's credentials or `$SYNTHETIC_API_KEY`; SearXNG needs `$SEARXNG_URL` pointed at your instance. |
| `code-search/` | Code search across public GitHub repositories via Sourcegraph's public API. `code_search` tool queries millions of repos with optional filters for language, repository (`owner/repo`), and path. No API key required. |
| `gondolin/` | Gondolin micro-VM sandbox. Routes all built-in tools (`read`, `write`, `edit`, `bash`, `grep`, `find`, `ls`) and `!` commands inside a QEMU micro-VM. Host cwd is mounted at `/workspace` in the guest. Requires QEMU and Node.js >= 23.6.0. |
| `status-bar/` | Starship-inspired two-line footer plus a polished input editor. Line 1 shows cwd, a Gondolin workspace segment when active, git state, context usage, tokens, and cost. Line 2 shows transient extension statuses (omitted when empty). Toggle with `/statusbar`. |
| [`tool-style/`](extensions/tool-style/README.md) | Gives agent tools, direct `!command` output, and extension messages a pywal-derived darker surface with state-colored rails. Toggle with `/toolstyle:toggle`. |
| `clear/` | Aliases `/clear` to `/new` for muscle memory from Claude Code and `clear`-keyed tools. Discard confirmation is handled by the underlying `/new` behavior. |
| [`voice/`](extensions/voice/README.md) | Local dictation and speech playback with sherpa-onnx and ONNX Runtime. `/voice` opens one settings modal for dictation, speech, voice, and connection status. Hold Space to dictate; use `/voice-speak` to summarize and read the latest response aloud. |
| [`worker-model/`](extensions/worker-model/README.md) | One enforced global model for delegated worker sessions. `/worker-model` selects it; the current choice appears in the input bar. Delegates fail descriptively when unconfigured. |
| [`small-model/`](extensions/small-model/README.md) | One global model for handoff, BTW, session recap, and voice summaries. Use `/smallmodel` to select it; the current choice appears in the input bar. |
| [`missions/`](extensions/missions/README.md) | Durable missions: long-lived objectives with a task graph, checkpoints, decisions, and budget, persisted in the project across restarts. `reconcile` re-runs done tasks' verification commands and flags regressions. |
| [`messenger/`](extensions/messenger/README.md) | File-based coordination between Pi sessions sharing a project: presence, mailboxes with automatic delivery into the conversation, and path reservations that block other sessions' edits. |
| [`agents/`](extensions/agents/README.md) | Multi-agent workflows: delegate bounded tasks to Gondolin-sandboxed worker sessions. Mutating workers use isolated git worktrees; plan-mode workers get research-only tools. Collect reports and patches through the durable worker registry. |
| [`autoresearch/`](extensions/autoresearch/README.md) | Autonomous experiment loop: measure a metric, keep improvements (commit), discard regressions (revert), repeat with correctness gates and descriptive spread scoring. |

Per-extension configuration (flags, env vars, config files) lives in each extension's own `README.md` under the **Configuration** section.

## Development

### Type declarations

Extensions can import types from the `"pi"` module for IDE autocomplete and compile-time safety:

```typescript
import type { ExtensionAPI, ExtensionContext } from "pi";

export default async function (pi: ExtensionAPI) {
  pi.registerCommand("hello", {
    description: "Say hello",
    handler: async (_args, ctx: ExtensionCommandContext) => {
      ctx.ui.notify("Hello!", "info");
    },
  });
}
```

Type stubs live in `types/pi.d.ts` and cover `ExtensionAPI`, `ExtensionContext`, `ExtensionCommandContext`, `ToolDefinition`, event types, and common TUI helpers.

### Creating a new extension

Use the scaffolding script to generate boilerplate:

```bash
npm run create my-feature
```

This creates `extensions/my-feature/my-feature.ts` and `test/extensions/my-feature.test.ts`.

Or create manually:

1. Create `extensions/<descriptive-name>/` and add `<descriptive-name>.ts`
2. Implement your extension using `import type { ... } from "pi"`
3. Validate: `npm run validate:one extensions/<name>/<name>.ts`
4. Test live: `pi -e extensions/<name>/<name>.ts`
5. Format and lint: `npm run format`
6. Run full check: `npm run check`
7. Commit

### Validation

Validation logic lives in `lib/validate-extension.ts`. CLI entry points are in `scripts/`:

```bash
npm run validate          # Validate all extensions (no subprocesses)
npm run validate:one <path>  # Validate a single extension
```

Checks run on every extension:
- Valid TypeScript syntax
- Required default export (async function)
- No undeclared npm imports
- At least one pi API call (`registerTool`, `registerCommand`, `on`, `appendEntry`, or `registerProvider`)

### Secret scanning

A [gitleaks](https://github.com/gitleaks/gitleaks) config lives at `.gitleaks.toml` and runs two ways:

- The husky pre-commit hook runs `gitleaks protect --staged` so secrets are caught before they leave the machine. The hook skips silently if gitleaks isn't installed locally; install it for early feedback:
  - Fedora: `sudo dnf install gitleaks`
  - macOS: `brew install gitleaks`
- The CI workflow runs gitleaks on every push and pull request as a required check, so commits without a local install still get blocked at the server.

The config extends gitleaks' default ruleset (~150 detectors for common token formats) and allowlists documentation placeholders like `syn_...` and `ctx7sk-...`.

### Testing

Shared mock factories live in `test/mocks/`:

- `createMockPi()` — returns a mock `ExtensionAPI`
- `createMockContext()` — returns a mock `ExtensionContext`
- `createMockCommandContext()` — returns a mock `ExtensionCommandContext`
- `createMockUI()` — returns a mock `ExtensionUIContext`

Per-extension tests go in `test/extensions/<name>.test.ts`.

```bash
npm run test       # Run all tests once
npm run test:watch # Run tests in watch mode
```

## Rules

- **No external npm dependencies** without explicit justification. Pi transpiles extensions directly.
- **One responsibility per file.** A focused extension is easier to test and maintain.
- **Test interactively** with `pi -e` before committing.
- **Extensions must export a default async function.**
